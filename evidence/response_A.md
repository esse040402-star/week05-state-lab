# 요청 A 응답 원문

- 실행: 2026-10-18, 독립된 새 세션(Claude Code, claude-sonnet-5-5), 1회 실행
- 시작 폴더: 프로젝트(`week05_state_lab`)의 상위 폴더. 프로젝트 폴더 안에서 시작하지 않았다.
- 요청 원문: `할 일 완료·취소 기능을 구현하려면 어떻게 해야 하나요? 수정 계획만 알려 주세요.`
- 세션 기록상 도구 호출: Glob 2회, Grep 2회 (호출 입력은 기록에 없음). 파일 수정·생성 없음.

---

**할 일(Todo) 완료·취소 기능은 이 세션에서 확인할 수 있는 코드에 없어서, 일반적인 수정 계획만 정리했습니다.** 파일은 읽기만 했고 수정하거나 만들지 않았습니다.

이 세션의 작업 폴더는 비어 있었습니다. 가장 최근에 쓴 프로젝트(`...백엔드 작업\backend`)에서 `todo`, `할 일`, `complete`, `cancel`을 검색했는데, 그 백엔드는 게임 추천 서비스였습니다. 거기에는 할 일 항목이 없고, 취향 진단 세션의 완료(`POST /api/sessions/{id}/complete`)와 AI 백로그·스케줄 기능만 있었습니다. 대상 프로젝트가 따로 있다면 경로를 알려 주세요. 그러면 실제 파일 이름에 맞춰 계획을 다시 구체화하겠습니다.

## 수정 계획 (일반형)

1. **데이터 모델**
   - 할 일에 `status` 컬럼을 추가합니다. 값은 `pending` / `completed` / `canceled` 세 가지입니다.
   - 필요하면 `completed_at`, `canceled_at` 같은 시각 컬럼도 추가합니다.
   - 기존 `done` 불리언이 있다면 `status`로 마이그레이션합니다. 기존 데이터는 `done=true`이면 `completed`, 아니면 `pending`으로 채웁니다.
   - `status`는 CHECK 제약이나 Enum으로 제한합니다.

2. **상태 전이 규칙**
   - `pending → completed`와 `pending → canceled`만 허용합니다.
   - 이미 `completed`나 `canceled`인 항목에 다시 요청하면 `409`를 반환합니다. 존재하지 않으면 `404`, 다른 사용자의 항목이면 `403`입니다.
   - 완료나 취소를 되돌리는 기능(복원)을 둘지 먼저 정해야 합니다.
   - 취소는 삭제하지 않고 상태만 바꿉니다(소프트 취소).

3. **서비스 계층**
   - `complete_todo(id, user)`와 `cancel_todo(id, user)`를 만들어 전이 검증과 시각 기록을 한곳에서 처리합니다.

4. **API**
   - `POST /todos/{id}/complete`와 `POST /todos/{id}/cancel`을 추가합니다. 대안은 `PATCH /todos/{id}`에 `{"status": ...}`를 보내는 방식입니다.
   - 응답에는 갱신된 항목 전체를 담습니다.
   - 목록 조회 `GET /todos`에는 `status` 필터를 추가합니다. 기본값은 `pending`만 보여 주거나 전체를 보여 주는 쪽으로 정합니다.

5. **프론트엔드**
   - 각 항목에 완료·취소 버튼(또는 체크박스와 취소 아이콘)을 추가합니다.
   - 완료는 취소선, 취소는 흐리게 표시하고, 상태별 탭이나 필터를 둡니다.
   - 버튼을 누르면 즉시 화면에 반영하고, 요청이 실패하면 되돌립니다.
   - 취소처럼 되돌리기 어려운 동작에는 확인 절차를 넣습니다.

6. **테스트와 문서**
   - 정상 전이, 중복 요청(`409`), 없는 항목(`404`), 권한 없음, 목록 필터를 테스트합니다.
   - API 문서(Swagger)에 새 엔드포인트와 오류 코드를 반영합니다.

7. **적용 순서**
   - 마이그레이션 → 서비스·API → 테스트 → 프론트 순서로 진행합니다.

결정이 필요한 것은 두 가지입니다. 완료나 취소를 되돌릴 수 있게 할지, 그리고 취소한 항목을 목록에 계속 보여 줄지입니다.
